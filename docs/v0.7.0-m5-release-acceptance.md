It verifies persisted observations, failed assertion provenance, validated assessment references, investigation result hash/audit, existing incident association, CLI review, authenticated loopback dashboard review, SQLite integrity, and no approval or remediation record. ## Security and backward compatibility

- Assessment references are checked against persisted observations; cross-incident digest/identity mismatch, missing references, unsupported versions, invalid schema/status combinations, malformed records, result-hash mismatch, and failed audit-chain states produce rejection or unavailable projections.
- Sensitive key fields including `api_key` and `api-key` are redacted in persisted investigation evidence. Synthetic regressions verify the value does not appear in CLI or dashboard output.
- HTML-shaped prompt-injection text is escaped and displayed as inert text. Recommendations are labeled advisory; schema validation rejects command/remediation-like next steps. No view has an investigation, SSH, approval, or execution route.
- Legacy v0.6.0 investigations remain in schema v4 and render with assessment `NOT AVAILABLE`. No migration or historical audit rewrite was made.
- Dashboard detail remains session-authenticated and loopback-only. SQLite schema remains v4.
