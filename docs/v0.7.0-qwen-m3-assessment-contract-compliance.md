# RunbookOS v0.7.0 — Qwen M3 Assessment Contract Compliance

**Scope: offline only.** No llama-server, live inference, SSH, managed VM,
real diagnostic execution, remediation, or operational database was used.

## Findings

The Pilot 2 report records six syntactically valid assessment responses and
sanitized validator categories, but does not preserve raw provider responses.
The offline mocks below reproduce each recorded category; they do not recover
the original model output or prove that the same individual fields caused each
historical rejection.

| Pilot 2 case | Recorded category/location | What the offline reproduction establishes |
|---|---|---|
| `web-normal-01` | Schema invalid; `literal_error` at `assessment_status` | A status outside the three declared literals is rejected at that field. The historical literal itself is unknown. |
| `app-failure-01` | `invalid_assessment_status_combination` | `assessed` with no non-unknown suspected/supported classification fails the existing deterministic invariant. Historical response shape is unavailable. |

Pilot 2 reported 152–592 assessment completion tokens, zero outputs at the

and any additional defects cannot be reconstructed from sanitized traces.

## Schema and validator compatibility

The production M1/M2 validator remains unchanged. This matrix distinguishes
model claims from trusted adapter metadata and records the actual validation
rules rather than new rules proposed for the model.

| Field | Owner | Contract and deterministic checks |
|---|---|---|
| `observations` | Adapter | Copied from synthetic fixture evidence. Includes stable reference, action/diagnostic, execution and step identity, target, recorded result, assertion outcome and `unknown` verification provenance. Qwen must not emit or upgrade it. |
| `incident_id`, `investigation_id` | Adapter | Bound to the current fixture case and synthetic investigation. Not accepted from the model reply. |
| `schema_version`, `classification_catalog_version` | Adapter | Set to the existing v1 assessment schema and v2 classification catalog. |
| `inferences[]` | Qwen semantic claim | Each item has literal `claim_type="inference"`, non-empty statement and a non-empty unique evidence reference list. References must resolve in this investigation. |
| `hypotheses[]` | Qwen semantic claim | Literal `claim_type="hypothesis"`, statement, finite confidence in `[0,1]`; reference, missing-evidence and disconfirming-check arrays may be empty. A hypothesis with no references must have confidence `<=0.25`. |
| `classifications[]` | Qwen chooses from closed set | Category is one of `healthy`, `service_failure`, `connectivity_failure`, `network_failure`, `dependency_failure`, `resource_pressure`, `unknown`; confidence is finite `[0,1]`; supporting refs may be empty; status is `suspected`, `supported`, or `undetermined`. `unknown` requires `undetermined`. `supported` requires at least one reference, all pointing to verified evidence. A suspected classification without refs must have confidence `<=0.25`. |
| `unknowns[]` | Qwen semantic claim | Literal `claim_type="unknown"`, non-empty question, reference and `missing_evidence` arrays may be empty. `missing_evidence` must be an array of bounded strings. |
| `recommended_next_steps[]` | Qwen advisory text | Bounded non-empty strings only; deterministic guard rejects executable or mutating advice. Recommendations have no execution authority. |
| `overall_uncertainty` | Qwen judgment | Required finite JSON number in `[0,1]`. The validator imposes no additional coupling between this value and status/classification. |
| `assessment_status` | Qwen chooses from fixed literals | Exactly `assessed`, `partial`, or `abstained`. `assessed` requires a non-`unknown` classification with `suspected` or `supported` status. `abstained` permits only no classifications or classifications all marked `undetermined`. `partial` has no separate global combination rule, but all other validators still apply. Contradictory observations prohibit `assessed` and prohibit any `supported` classification. |
| `semantic_support_status`, `recommendations_are_executable` | Adapter/schema defaults | Remain `unverified` and `false`. Citation integrity does not establish semantic support. |

The adapter requires all seven reply keys even though the Pydantic reply model
has defaults for some collections. Every list must be JSON array syntax. Empty
arrays are valid where the schema allows them; inference references cannot be
empty. All confidence/uncertainty numbers must be finite. Malformed JSON,
unknown keys, invalid literals, and bad types remain rejected without repair.

### Evidence alias boundary

The trusted adapter derives case-local aliases `E01`, `E02`, … from the ordered
fixture observations and retains the private alias-to-fixture-reference map.
For the assessment request, each model-facing observation's `evidence_id` is
replaced by its alias; the canonical `syn:…` reference is not sent in that
stage's observation payload. The same exact alias list is supplied as
`evidence_refs`. The adapter accepts only those aliases, then deterministically
restores the original fixture references before the unchanged assessment
validator runs. Empty reference arrays remain possible for fields whose schema
allows them. Unknown aliases fail closed. No evidence status, observation,
classification, confidence, abstention, or causal content is synthesized by
the adapter.

## Contract ownership and prompt changes

Qwen authors semantic content: inference/hypothesis/unknown statements,
classification category and status, confidence values, uncertainty,
assessment status, and advisory next steps. The adapter owns observations,
stable provenance, incident/investigation IDs, schema/catalog versions,
alias mapping, and the fixed unverified/non-executable metadata. The evaluator
alone owns ground truth; no gold label or annotation rationale is placed in the
provider request.

The revised test-only prompt now states exact status literals and combinations,
all top-level and nested field names/types, array requirements, the closed
classification set, alias-only references, empty-list behavior, the
unverified-evidence restriction, and advisory-only recommendations. It shows
generic shape-only abstention and assessed examples, explicitly not tied to a
benchmark case. Contradictory observations are called out. The strict
single-object JSON parser and all validators remain authoritative.

Before this change, the prompt named enums but did not spell out the exact
status-combination conditions, showed only abstention, and described nested
objects in prose without complete JSON shapes. The assessment adapter also
included canonical fixture evidence IDs in observation objects alongside the
short aliases. It now substitutes each observation ID with its case-local
alias in the assessment request; the trusted adapter retains the canonical
mapping and restores it before validation.

No smaller alternate reply protocol was introduced: that would change what the
benchmark measures and is not needed to reproduce or explain the recorded
failures. The output limit remains **700 tokens for selection and 700 for
assessment**, with the existing 120-second timeout and no retry. Pilot 2's
assessment responses were 152–592 tokens; a future run can establish whether
the clarified contract improves conformance, but offline tests cannot establish
Qwen compliance or quality.

## Offline regression

Six mocked responses are keyed to the six Pilot 2 case IDs and reproduce the
recorded categories: unsupported status literal, two distinct invalid status
combinations, incorrect nested list type, and two forged evidence references.
Tests verify safe rejection, exact sanitized locations/categories, retained
valid selection, two calls per case (no retry), and no persisted assessment on
failure. They are controlled reproductions of categories, not reconstructions
of the unretained historical responses. Additional tests cover a valid
minimal abstention, a valid assessed response, alias replacement, and fixture
observation verification remaining `unknown`.

Focused AI/assessment/M3 tests: **93 passed**. Full offline suite: **300
passed, 11 skipped**; skips are opt-in live AI, SSH, probe, and tunnel tests.
Repository Ruff lint passed; formatting passed for all Python files under
`src`, `tests`, and `scripts`; `git diff --check` passed.

Offline mocks prove validator behavior and prompt/adapter wiring only. They do
not show that Qwen follows the revised instructions. Citation validity is
separate from semantic support; semantic support remains unverified. The next
experiment, if separately approved, should use the same six fixed cases,
unchanged validators and gold labels, the existing 700/700 token budgets, and
the existing request/resource guards. Compare its sanitized stage traces with
Pilot 2; do not broaden scope or count missing assessments as abstentions.
