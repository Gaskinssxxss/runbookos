## M3 evaluation (six-case scope only)

The prediction artifact was re-evaluated offline after the run. Review found
that a stage-two timeout had caused the original adapter projection to omit an
already-valid stage-one selection. The test-only projection was corrected to
score a catalog-validated selection independently of assessment completion;
then the existing evaluator was rerun against the preserved prediction
artifact. No new inference was made, and the original generated evaluation
files remain preserved alongside the explicitly named reevaluation files.
That narrow post-run code change affected only evaluator projection: a
catalog-valid selection is retained when its subsequent assessment request
fails. Prediction generation and the stored prediction artifact were not
changed; the separate adapter fingerprints above identify the generation and
reevaluation code.

## Comparison and limitations

The earlier 24-case run processed 30 requests, accepted zero assessments, and
reported 18 invalid selection JSON responses plus six catalog-valid selections
followed by invalid assessments. This pilot’s selection contract improved:
six selections parsed and passed catalog validation. The assessment contract
remains unreliable: four parse failures suspected to be incomplete output, one
timeout, and one accepted abstention. The different case set and sizes mean
these pilot rates are not a substitute for a full-benchmark comparison.

No SSH, tunnel, managed VM, real diagnostic execution, remediation, deployment,
or operational database access occurred. No gold labels were changed. The run
does not establish production incident accuracy or semantic correctness.
