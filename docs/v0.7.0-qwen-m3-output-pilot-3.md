## Comparison with Pilots 1 and 2

All three runs used the same six case IDs and 12-request ceiling. Pilot 1 used
the earlier assessment prompt; Pilot 2 used a compact prompt that reduced
output length; Pilot 3 used the explicit status/schema examples and
case-local evidence-alias substitution from the offline contract fix.

| Measure | Pilot 1 | Pilot 2 | Pilot 3 |
|---|---:|---:|---:|
| Requests | 12 | 12 | 12 |
| Selection valid | 6/6 | 6/6 | 6/6 |
| Diagnostic exact match | 5/6 | 5/6 | 5/6 |
| Assessment JSON valid | 1/5 returned; 1 timeout | 6/6 | 6/6 |
| Accepted assessments | 1/6 | 0/6 | 2/6 |
| Main assessment failures | 4 at cap, 1 timeout | 2 status combinations, 2 schema, 2 forged refs | 4 `claim_type` literal schema failures |
| Completion cap / timeout | 4 at 700 / 1 timeout | 0 / 0 | 0 / 0 |

Pilot 3 improved accepted assessments from 0/6 to 2/6 versus Pilot 2, and
eliminated the previously observed status, nested-list, and forged-alias
categories in this sample. It did not yield any non-abstained assessment or
classification coverage. Selection performance did not change. The remaining
`claim_type` failures indicate that asking the model to emit redundant literal
discriminators is still unreliable. A future design review could evaluate a
versioned test-only response shape that omits those fixed discriminators and
has the adapter supply them from the containing list field. That would change
the measured model-output contract; it needs offline validation and separate
approval before another inference run. Do not auto-rerun or relax the
StructuredAssessment validator.

No SSH, tunnel, managed VM contact, real diagnostic execution, remediation,
deployment, gold-label modification, or operational database access occurred.
No file was staged or committed. Historical Pilot 1 and Pilot 2 artifacts
remain unchanged.
