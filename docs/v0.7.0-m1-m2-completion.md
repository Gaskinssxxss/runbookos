# RunbookOS v0.7.0 M1/M2 Completion

Status: implementation complete; ready for review

## Implemented

- Added strict, versioned assessment models in `runbookos.assessment`.
- Direct observations are constructed from diagnostic step results, not authored
  by the model. They retain stable execution/step refs, diagnostic/action,
  target, step finish timestamp, result, assertion outcome, execution status,
  prior verification status, and incident/investigation association.
- Structured model claims now support evidence-bound inferences, hypotheses,
  closed-v2 taxonomy classifications, unknowns, uncertainty, and advisory next
  steps. The output is marked `semantic_support_status: unverified`.
- Deterministic validation rejects unsupported schema versions/categories,
  non-finite or out-of-range confidence, duplicate/missing evidence refs,
  unsupported high-confidence claims, supported classifications without verified
  evidence, conflicting direct observations presented as completed support, and
  command/remediation-shaped recommendations.
- The legacy `report` remains available. The v0.6.0 hypotheses and
  recommendations response shape remains accepted; absent classification
  output becomes partial or abstained, never a fabricated class.
- Incident-bound CLI investigations pass their incident ID into the assessment.
  Persistence accepts the already-generated investigation ID and verifies it
  matches the embedded assessment ID.

## Architecture and compatibility

`docs/adr-evidence-aware-investigation-v0.7.0.md` records the pre-implementation
findings and decision. SQLite remains schema v4: the assessment is an additive
field inside the existing investigation JSON, and the existing audit result
hash covers it. No migration or historical-row rewrite was made. A regression
test reopens a schema-v4 database containing a legacy v0.6.0 investigation and
checks the record and audit chain remain unchanged.

Diagnostic selection, catalog membership, planning, policy checks, execution,
and action IDs are unchanged. The dashboard is unchanged. Recommendations do
not authorize execution; all diagnosis execution remains operator initiated and
engine controlled.

## Limitations and M3 readiness

Reference validity, schema consistency, assertion state, and supported-status
requirements are deterministic. Semantic entailment—whether a natural-language
claim truly follows from the cited result—cannot be proven by these checks and
remains explicitly unverified. The confidence value is model-reported, not a
calibrated probability. Human review or a separately designed blinded semantic
evaluation is still needed.

M1/M2 are ready for review. M3 can proceed after review, with semantic support
evaluation treated as a separate quality measure rather than inferred from
valid citations.
